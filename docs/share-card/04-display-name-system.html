The display name system

One visual system, one voice, no pronouns. The owner's display name is the subject of every card, so a person, a company, a creator, a project and a fan community all pass through the same template with no branching.

Recommendation — default direction

Presence. It is true on the first day and in the tenth year, it needs no eligibility check, it carries no claim about value, and it is the only one of the three that reads correctly for every kind of owner without supervision. Ship it as the default and treat the other two as opt-in variants.

{displayName} is on the globe.
{count} of 1,000,000 hexagons claimed.

1:1 · 1080×1080

Identical structure, identical type scale, identical layout. The only variables are display name, count, hexagon ID and date. Nothing branches on who the owner is.

One wrinkle worth knowing about. Removing pronouns does not remove grammatical number. "Million Hexagons Fans is on the globe" reads slightly wrong to some people, and no reliable rule detects a plural display name. Two honest options: accept it — collective names routinely take a singular verb and the awkwardness is mild — or use the agreement-free headline "{displayName} — now on the globe." everywhere, which never breaks but loses a little punch. The third card above uses the Permanence template, which happens to sidestep it; that is not a rule you can rely on. My call: keep "is on the globe" and accept the rare soft edge.

The three directions, one voice

All pronoun-free, all name-first, all sharing the universal CTA.

Threshold rule for "early". Set earlyEligible to true at the moment of purchase when the placement falls inside the first 10,000 claims (1% of inventory), and store it on the record. Never recompute it later: the card must say the same thing in year five as it did on day one, and a live check would silently switch a buyer's card from "got here early" to "is on the globe" behind their back.

Final copy, every format

The only copy that changes between formats is the last line. Where a link is clickable the universal CTA stands; where it is not, the CTA is replaced by a search instruction, because "see it on the globe" is a broken promise on a platform with nothing to tap.

Where everything sits

Same order on every ratio. Landscape runs it left-to-right instead of top-to-bottom; nothing is resequenced.

  1. Display nameLargest element. Answers who. Never truncated below 44 characters.
  2. Claim countDirectly beneath, one step down. Answers what happened and gives the scale its meaning against 1,000,000.
  3. The globeThe visual proof. Answers why it matters — the artwork sits in the claimed cells.
  4. CTA or instructionAccent colour, sans, one line. Answers how to find it.
  5. Hexagon numberLast, in a hairline token. An address, not an action. Present on every card so a screenshot still resolves.
  6. Date & wordmarkMono, muted, top edge. Provenance for anyone who looks twice.

Display name handling

The name is now load-bearing, so its length has to be a spec rather than a hope.

  • 1–18 characters — headline at 60px. "Craig Duffy", "Northbound Coffee"
  • 19–30 characters — 50px. "Million Hexagons Fans"
  • 31–44 characters — 42px, wraps to three lines.
  • 45+ characters — truncate at 44 with an ellipsis. Show the truncation live in the editor so it is never a surprise on the card.
  • No name set — the sentence loses its subject, so the card falls back to "A new place on the globe." with the count and number unchanged. Nothing is placeholdered.

What makes it less certificate

Five changes, cheapest first.

  • Name the scale, not the total. "48 of 1,000,000" makes a small claim feel deliberate; a bare "48 hexagons" makes it feel minor.
  • Show neighbours on the globe. A few other claimed clusters visible around the owner's proves it is a shared place, not an empty vanity map.
  • Let the globe be posed, not fixed. Rotate so the claim sits slightly off-centre. Dead-centre framing is what makes a certificate a certificate.
  • Give the count a live counterpart. "48 of 1,000,000 hexagons claimed" invites the question "how many are left?" — and the answer is your site.
  • Drop the border. The card currently has a hairline frame. Frames say diploma. Let the artwork and globe run to the edge instead.

Simplest implementation

Copy is data, layout is a stylesheet, output is one canvas. No server rendering, no template branching, no new dependency. One pure function produces every string on every card, which is also what makes the copy reviewable without opening the renderer.

// src/share/card-copy.js — the whole copy system

const TOTAL = 1000000;

// name and tail stay separate so the name can be set in lime
export const DIRECTIONS = {
  presence:   { tail: ' is on the globe.',
                sub:  c => `${c} of 1,000,000 hexagons claimed.` },
  early:      { tail: ' got here early.',
                sub:  c => `${c} hexagons claimed while the globe` +
                           ` was still mostly empty.` },
  permanence: { tail: ' has a place on the globe.',
                sub:  c => `${c} of 1,000,000 hexagons.` +
                           ` Claimed permanently.` }
};

export function cardCopy(record, ratio) {
  const d = DIRECTIONS[record.direction] ?? DIRECTIONS.presence;
  const name  = displayName(record);
  const count = record.cells.length.toLocaleString();
  const linkable = ratio === '1x1' || ratio === 'og';

  return {
    // renderer wraps `name` in the accent colour, `tail` stays ink
    name: name || '',
    tail: name ? d.tail : 'A new place on the globe.',
    sub:  d.sub(count),
    // the ONLY place format changes the words
    action: linkable
      ? 'See it on the globe →'
      : `Search ${record.hexId} to find it`,
    hexId: `#${record.hexId}`,
    date:  formatDate(record.claimedAt),
    url:   'millionhexagons.com'
  };
}
  • One function, no branching on owner type. displayName() returns the company name, the account name, or empty — and the card never asks which it was.
  • Direction is a stored field on the placement, defaulting to presence. early is only offerable when earlyEligible was set at purchase.
  • Four ratios are four CSS classes over identical markup, exactly as rendered on this page. The 1080px base means every size in the stylesheet is the real export size.
  • Rasterise without a library. Serialise the card's SVG, draw it to a canvas at 1× or 2×, then toBlob. The globe is already SVG here; the artwork is an image you control.
  • Reuse the real globe instead. You already render one in src/globe — capturing the live canvas with the claim lit gives a better picture than any redraw, and the flyover concept later needs that capture path anyway.
  • Captions ship from the same object, so the post text and the card can never disagree about the count or the number.

What I would change about your spec

Two things, both small. The universal CTA cannot be fully universal — on Instagram and TikTok "See it on the globe →" points at nothing tappable, so it has to become the search instruction. That is the one permitted format branch, and it is about the platform, never about the owner.

And "early" should be a stored flag, not a rule evaluated at render time. Otherwise a buyer's card quietly changes what it says about them as the globe fills, which is worse than never having offered the direction.

Everything else holds: one visual system, name as subject, no pronouns, no owner-type templates, number demoted to an address.
